Схема архитектуры проекта
Браузер пользователя потом Nginx (порт 443, SSL) и затем:
  если запрос к `/api/` то Backend (Node.js, порт 3000)
  если запрос к `/` то Frontend (Nginx со статикой, порт 80)

Таблица сервисов
| Сервис      | Технология        | Внутренний порт | Продакшен-сервер  |
|-------------|-------------------|-----------------|-------------------|
| frontend    | HTML/JS/CSS       | 80              | Nginx             |
| backend     | Node.js (Express) | 3000            | node src/index.js |
| nginx       | Nginx             | 80, 443         |        -          |
| База данных | Supabase          |       -         |        -          |

Переменные окружения и секреты
`DATABASE_URL` (секрет)
`DIRECT_URL` (секрет)
`JWT_SECRET` (секрет)
`PORT` (переменная окружения)

Команды для запуска и остановки
Запуск: `docker compose up --build -d`
Остановка: `docker compose down`

Ошибки и их устранение
1. Ошибка: `failed to connect to the docker API...` - Решение: Запустить Docker Desktop и дождаться статуса "Engine running".
2. Ошибка: `Не удалось загрузить лоты` в браузере - Решение: Очистить кэш браузера (Ctrl+F5) и убедиться, что в `frontend.js` путь заменен на `/api` и в других файлаъ тоже.

Что нужно изменить для публикации на реальном сервере?
1. Арендовать сервер (VPS) с установленным Docker.
2. Зарегистрировать реальный домен (например, `avabid.ru`) и настроить DNS-записи (A-запись на IP сервера).
3. Получить настоящий SSL-сертификат и заменить локальные сертификаты в конфиге Nginx.
4. Убрать привязку к `127.0.0.1` в `docker-compose.yml`, чтобы порты были доступны извне.
